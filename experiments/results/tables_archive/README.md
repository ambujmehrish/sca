# Archived tables — DO NOT CITE NUMBERS FROM THIS DIRECTORY

Everything here is a `.tex` file that **no generator produces**. Nothing in the
repo reads these files and no table in the paper is built from them. They are
kept for provenance only.

The rule this directory exists to enforce: **every table in the paper comes from
`experiments/results/tables_final/`, and every file in `tables_final/` carries a
`%% Generated by scripts/...` header.** `scripts/check_tables_generated.py`
enforces it; the harvest runs it.

The failure this prevents actually happened. Contribution 1 of the first draft
read "performance comparable to full fine-tuning under the same protocol (53.4
vs. 53.5 R@1)". Those two numbers came from `table1_main.tex` below, and they
contradicted the paper's own §4.1 ("decreases by 4.2 on MSR-VTT") and its own
Table 1 (50.4 vs 54.6). The generated tables were right; the hand-maintained
file was five days stale and nothing regenerated it.

## Known wrong — never reuse

- **`table1_main.tex`** — bolds SCA at learning rate 1e-4 (54.9) as the headline
  while every generated table reports T9 at 2e-5 (54.6); its own caption admits
  per-row learning-rate selection ("Each SCA row is at its better pretraining
  learning rate"). Its full-FT row reads 53.4 where the generated table reads
  50.4, and its LoRA-at-2e-5 row reads 53.5, which is not any T9 seed
  (54.8/54.7/54.4). It also carries `\label{tab:main}`, colliding with
  `table1_main_all.tex`. It additionally prints published numbers with no entry
  in `benchmark_eval/published_rows.json` (ImageBind 36.8/70.0, VAST V->T
  49.0/76.2).
- **`table2_aggregator.tex`** — predates the "aggregation tax" -> "aggregation
  gain" rename and still shows a dash for the GRAM/MSR-VTT cell that
  `table_gain.tex` now measures as -3.4. Superseded by `table_gain.tex` and
  `table_gain_supp.tex`.

## Ungenerated, numbers not re-verified

The remaining files predate the current extractor chain. Some may hold correct
values -- `table7_env_audit.tex`'s numbers, for instance, match what the
supplement reports -- but none has been re-derived from the evaluation logs by a
generator, so none may be cited. If a number here is needed, add it to a
generator and let the generator emit it.
